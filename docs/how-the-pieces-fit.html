How spacewalk-mcp fits together

A map of the projects, the packages and who uses what. Accurate as of October 30, 2026.

Who uses the remote?

Two things: the server and the Viewer. The server reads the remote/ folder directly. The Viewer gets a copy.

Where do the tarball and npm come in?

Only in how the Viewer gets its copy. The server never touches either one.

Do I choose between the tarball and npm?

No. They're the same file in two different places. The Viewer uses the tarball until the package is on npm, then it switches. That switch is one line in one file.

Why does this project have so many package.json files?

There are four, and only one of them describes something meant to be shared with other projects. The other three just organize work inside this project.

What runs when someone uses it

Three things talk to each other. A person chats with Claude or ChatGPT, and the 3D structure appears in a web page beside the conversation.

A Room ties one conversation to the Viewers showing it, and it's the only place the current view is recorded. When the model makes a tool call, the Room updates and every Viewer in it redraws. When someone changes something by hand, the Viewer asks the Room to make the change.

Today, all of this only runs on your laptop. Nothing is deployed yet. Issue #11 covers the first deployment.

Why the difference matters

Once deployed, the server and the Viewer each hold a fixed copy of the message rules, and those copies can fall out of step. If you change the rules and raise PROTOCOL_VERSION, a Room refuses any Viewer with the old number and shows "This viewer is out of date: reload the viewer." Reloading only helps once a Viewer built with the new tarball has been deployed.

So a change to the message rules takes three steps: release a new tarball, update the Viewer's address, then deploy both the server and the Viewer.

Tarball and npm: the same file on different shelves

A tarball is a single compressed file holding a folder of code. npm stores every package this way. Publishing to npm puts the file on npm's shelf, where it's found by name. Our stopgap puts the identical file on a GitHub release, where it's found by web address.

Words used here

RepoOne project on GitHub. There are two here: spacewalk-mcp and spacewalk.
PackageA folder of code with a package.json file.
ServerThe code in server/. It runs as a Cloudflare Worker, Cloudflare's name for a small program it hosts. Conversations and Viewers both connect to it.
ViewerThe web page showing Spacewalk's 3D view, attached to one Room.
RoomWhat ties one conversation to the Viewers showing it.
RemoteThe package @aidenlab/spacewalk-remote, the code in remote/.
Message rulesThe exact form of the messages passed between a Viewer and a Room. The code calls this the protocol.
TarballA single compressed file holding a folder of code. It ends in .tgz.
